# 思而行 · RAG 检索增强评测报告（2026-10，8 题）

> 一句话结论：**接上 RAG 后，答案要点命中率从 35.8% 提升到 85.0%（+49.2pt）；无 RAG 时 8 题里有 2 题完全答不出来（0 命中）。**

## 1. 要回答的问题

思而行有一个资料库（本项目当前库里 493 条：JD、面经、方法论、教程）。问题是：**把这些资料检索出来喂给模型，到底有没有让答案更准？** 如果没用，这个功能就该砍掉。

## 2. 方法（两臂对照 + 盲评）

| 项 | 设置 |
| --- | --- |
| 实验设计 | 同一批题、同一个模型、同一套提示词，**唯一变量 = 提示词里有没有注入检索到的资料片段** |
| A 臂（RAG） | 按问题检索资料库，取最相关片段注入提示词 |
| B 臂（no-RAG） | 完全不给资料，只让模型凭自身知识回答 |
| 题库 | 8 题，全部是「答案只能来自资料库」的事实型问题（岗位硬性条件、面试流程细节、行业判断），**模型不可能先验知道** |
| 判分 | 每题预先写 3–5 个「必须出现」的要点，逐点判定是否命中（命中数 / 总要点 = 该题得分） |
| 盲评 | 打分时不知道答案是哪个臂产出的 |
| 总要点数 | 38 个（7 题 × 5 点 + 1 题 × 3 点） |

## 3. 结果

| 总要点命中（点 / 总点） | **32 / 38（84.2%）** | 13 / 38（34.2%） | +19 点 |

## 4. 三条失败样例（无 RAG 臂）

1. **q21（莉莉丝一面）0/5**：模型编了一套「通用 AI PM 面试流程」，把考察点写成"算法、数学基础"，而资料原文是"两段实习问得很细、代码能力、大模型原理、入职时间"。**典型幻觉——说得像真的，但和这家公司无关。**
2. **q23（百度 ACG 一面）0/5**：不知道面试时长（34 分钟）与分组安排（机器人 / 数字人），整题空转。
3. **q19（美团智能学习）只命中 3/5**：方向答对，但漏掉"经验不限 / 本科 / 所属业务线"三个硬事实——这类漏点直接等于 HR 筛人时对不上。

## 5. 结论与下一步

- **结论 1**：对这个产品，RAG 不是"锦上添花"，是**从不可用到可用**的分界线（35.8% → 85.0%，且有 2 题归零）。
- **结论 2**：失败模式高度集中在「跨来源的具体事实」上，说明检索召回正确 ≠ 答案正确，还需要**引用回填**（让模型必须标注来源片段）才能继续压幻觉。
- **下一步（按优先级）**：
  1. 题库扩到 20 题，补「否定题 / 多跳题 / 长文题」三类，避免题目偏简单导致虚高；
  2. 加「引用必须可溯源」约束，统计无出处断言比例；
  3. 记录耗时与 token，算清一次问答的成本。

## 6. 复现

思而行内置该评测（目标页 →「检索增强评测」）：题库、两臂、逐题得分与失败样例都在本机库表 `bench_questions` / `bench_runs` / `bench_results` 里，可随时重跑对比。
